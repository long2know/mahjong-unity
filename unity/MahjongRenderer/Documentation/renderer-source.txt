MahjongRenderer U1 source project
================================

This is a Unity renderer, not a rule engine, browser shell or network client.
The entry scene Assets/Scenes/MahjongRenderer.unity is already connected to
MahjongBridge and the original surface shader. It creates real meshes, separate
table/hand cameras, source slot colliders, public labels, dice and input handlers.
No sample projects, third-party fonts or networking SDKs are imported.
Pinned creator CC0 face/back artwork and the existing CC0 fabric texture are
documented, with exact original and derivative hashes, in art-provenance.json.
The byte-identical creator notice is Assets/Art/FluffyStuff/LICENSE.md.

Pinned toolchain
---------------
Unity 6000.3.24f1, revision 4e7b9b5b6244, with legitimately provisioned Web Build
Support and valid editor licensing. This is a reproducibility pin, not a latest
patch claim. Newtonsoft 3.2.1 and Unity Test Framework 1.4.6 are manifest pins;
no package restore or editor import is implied by this source delivery.
The build method enforces IL2CPP, OpenGLES3/WebGL2, single-threaded execution,
disabled compression, no decompression fallback, no wasm2023 and no data caching.

Build/test producer
-------------------
Default: Backend's repo-managed GameCI container wrapper (Backend owns its
image digest, mounts and licensing configuration). No image pull, installation
or activation occurs automatically. Docker does not remove Unity's license gate.
The producer is container-compatible with UNITY_EDITOR=/opt/unity/Editor/Unity.
It requires bash, git and python3 plus the provisioned editor. .git and the source
inputs must be accessible. Project/cache/output paths must be writable.

Optional approved editor invocation from product root:

  UNITY_EDITOR=/approved/Unity/Hub/Editor/6000.3.24f1/Editor/Unity bash scripts/build-unity-webgl.sh --test
  UNITY_EDITOR=/approved/Unity/Hub/Editor/6000.3.24f1/Editor/Unity bash scripts/build-unity-webgl.sh --test-and-build

Build executeMethod: Mahjong.Renderer.Editor.WebGlBuild.Build
Actual editor arguments: -batchmode -nographics -quit -buildTarget WebGL.
Tests use -runTests -testPlatform EditMode, without -quit.
The Editor-only test assembly explicitly references each Unity test runner once
and the restored nunit.framework.dll and Newtonsoft.Json.dll. Do not combine
those runner references with legacy optionalUnityReferences: TestAssemblies;
the real Editor adds duplicate runners and restricts implicit DLL references.
Empty TagManager layer entries are quoted strings; bare dash-only entries fail
the pinned Editor's project-settings parser. EditMode checks the imported
rendering/picking layer names, not just their source text.
Actual outputs: artifacts/unity-webgl/{Build/*,renderer-build.json}
Actual editor evidence only:
  artifacts/test-results/unity-webgl-build.log
  artifacts/test-results/unity-editmode.xml
  artifacts/test-results/unity-tests.log
Subordinate tool scratch/cache: unity/MahjongRenderer/BuildCache/tool-work.
No license or environment files are read by the producer. There is no simulated
loader, data, WebAssembly output or success manifest when the editor is absent.
Missing editor/module/license/import/compile/report/files are nonzero failures.

Manifest/provenance
-------------------
renderer-build.json is exactly frozen BuildManifest v1.0.0, no extra fields.
It is emitted only after real BuildPipeline.BuildPlayer success and validation
of distinct nonempty loader/framework/data/wasm files, SHA256 and wasm magic.
Backend owns release validation and rejects sourceDirty/developmentBuild;
explicit local dirty qualification must still disclose the actual source.

Tools/source_metadata.py hashes the sorted relative renderer source paths,
NUL, each file's binary SHA256, NUL. Source input directories are Assets,
Packages, ProjectSettings, Tools and Documentation plus the producer script.
Generated renderer-build-identity.json/.meta, caches and secret/license names
are excluded. rendererSourceRevision is actual git HEAD. sourceDirty is real
git status scoped to those same inputs: it does not mean the entire repository
is clean, and avoids false deletions from Backend's partial container mounts.
Metadata is measured after actual editor import/settings normalization; a source
hash/revision change during BuildPlayer fails instead of mislabeling artifacts.
No wrapper-supplied revision, hash or dirty override is accepted.

Frozen browser boundary
-----------------------
Receiver GameObject: MahjongBridge
SendMessage methods, one UTF8 JSON string:
  Configure, Clear, ApplyLayout, ApplyFrame, SetViewport, SetPlayback,
  ReceiveActionResult
Outbound: Assets/Plugins/WebGL/MahjongBridge.jslib invokes exactly
window.MahjongUnityBridge.emit(jsonString).
Only ready, frameRendered, action and error are emitted. There are no extra
frameVersion/generation fields or Unity network connections.

Configure is one matching build/instance handshake. Clear binds fresh session
epochs and blanks both frame buffers, identities, labels, hand and gesture state.
Layout/frame are complete replacements. FrameId remains monotonic throughout
an epoch even on a layout rebuild. ResizeRevision is monotonic within an instance.
Unknown properties/enums/version, JSON extensions, duplicates, nonfinite/unsafe
geometry, impossible references and stale instance/session/frame/action replies
are errors; rejected frames do not replace the previous complete frame.
FrameRendered requires table (and separate-hand when enabled) Camera.onPostRender
receipts plus WaitForEndOfFrame and matching current session/frame/backing buffer.
Parsing JSON or constructing meshes does not imply a rendered-frame receipt.
Accepted-frame composition/face/privacy is immediate; visual interpolation
between persistent entities uses only accepted poses and moves the same collider.
FrameRendered is a real camera receipt, not an animation-completed event.

Assets/WebGLTemplates/MahjongHost is an external-script, no-eval producer host.
It loads only manifest-listed real Unity outputs, configures the exact bridge,
measures viewport/DPR/insets and exposes MahjongRendererSourceHost for supplying
explicit viewer-safe layout/frame inputs. It intentionally has no demo/rules
or initial fake frame. Frontend's production host/shell remains Frontend-owned.

Presentation/input source capabilities
--------------------------------------
Visual artwork and materials
----------------------------
Traditional faces use FluffyStuff/riichi-mahjong-tiles Regular at
26e127ba2117f45cdce5ea0225748cc0cfad3169 (CC0). All37 PNGs and SVG masters,
Back.png/Back.svg, README and the exact LICENSE.md are retained outside
Resources for traceability. The player loads only two1536x1536 precomputed
atlases, two192x288 recolored backs and one512x512 Fabric030-derived fork JPEG;
it never constructs37 full-resolution CPU face arrays. Imported textures are
not CPU-readable, use intentional normal-quality compression, trilinear mips
and clamped atlas edges (repeating fabric). Worst-case imported RGBA/mip
fallback is below28MB; original generated sticks/dice/marker add below2MB.

Atlas cells are192x288 (native2:3); source600x800 artwork is Lanczos-resized to
168x224 (3:4) inside transparent padding, never stretched to tile proportions.
Cells run from the PNG bottom-left, while glyph top maps to face +Z. The
material composites artwork on matching ivory; index31 Haku is intentionally
blank white dragon,32 Hatsu is green,33 Chun is red. Faces34..36 are red fives.
Optional labels occupy only the lower letterbox, with original antialiased
rounded-stroke labels and corrected WD/GD/RD mapping. Unknown surfaces bind
only the separate common back0/1 textures, never a face UV or label.

Original beveled/rounded body meshes retain the exact canonical BoxCollider,
SourceCoordinates bounds and bevel width; tiles/dice use96 vertices and44
triangles with smooth edge normals and small chamfered corner facets rather
than a dense shoulder grid. The table/rail retain their rounded96-vertex,
108-triangle mesh.
The rounded rail/inlay use a shared104-vertex shell: their hidden full-screen
top/bottom interiors are omitted, with an opening conservatively covered by
even the minimum rectangular felt. Felt writes depth before the remaining rail.
Colored lower bases, satin highlights, textured
tinted felt, original rail grain/inlay, a small center inset and vector public
labels are presentation only. Contact shadows/cue outlines have no colliders
and use a late transparent material with depth writes OFF; idle empty-slot
pads are hidden, while canonical slot targets and pickup/drop outlines remain.
Normalized body height is stored in a second UV channel so two-tone bases
remain correct under Unity dynamic batching. Face/back/die paint planes have a
small visual depth separation and the cameras use a0.025 near plane (inside
the existing fitted clearance), avoiding visible panel/body depth fighting.
Public phase/seat/center typography scales with projected CSS size, not DPR;
long phase labels are human-spaced and "AWAITING" is omitted from the visual
caption. Dealer/honba values remain source-defined. The console and interactive
outlines have no pick colliders, and do not change plan bounds, dice centers,
logical mesh sizes, camera fit, public DTOs or rule/action availability.
Both cameras use single-sample targets without MSAA render/resolve buffers;
imported glyphs retain trilinear mips and soft cues retain analytic edge coverage.
Satin diffuse/highlight lighting is interpolated from mesh
vertices; unlit labels/cues skip lighting and zero-gloss felt skips highlights.
Anisotropic filtering is1x for atlas/back textures and capped at2x for fabric
(whose unchanged importer records4x). It is enabled, not forced on, avoiding
the9x promotion of all imported samplers. The fabric-only sampling tradeoff
does not change glyph resolution, filtering, atlas pixels, table tint or DPR.
Opaque artwork/body surfaces replace pixels and write depth without alpha
clipping. Only soft cues and temporary translucent surfaces use alpha blending,
with depth writes OFF; temporary artwork retains the body's opacity.
Four shared material paths compile only the relevant plain, felt, wood or
decal effect; opaque tiles and labels do not evaluate shadow derivatives,
felt vignette or rail grain. These are fixed render paths, not device switches.
Atomic frame deactivation hides public labels without invalidating their vector
mesh cache. Only changed text or projected height rebuilds the bounded16 label
meshes across both buffers; cleared/unused labels remain invisible.
No HDR, realtime shadow maps, URP, postprocessing stack or new package is required.

The deterministic offline atlas builder uses Pillow only for regeneration:
  python3 unity/MahjongRenderer/Tools/build_art_atlas.py --source-root <audited-originals> --receipt <pinned-file-receipt> --table <verified-table.jpg>
Its no-argument integrity/real-pixel check uses only Python's standard library
and runs in the normal source gate. Rebuilding changes documented derivative
hashes, not the creator originals. Actual GPU antialiasing/rendering and
device-specific compression/fallback remain native-player qualification facts,
not claims established by the source checker.

Classic conversion retains the supplied right-handed Z-up coordinates at
0.01 units, (x-87,z,y-87), quaternion (-qx,-qz,-qy,qw), and applies POV rotation
once. Logical colliders retain original shape and uniform scale; the visual body is
beveled within those same logical bounds.
Rectangular relay layout rigidly packs each seat/group into measured,
non-overlapping lanes without repacking wall tiers/rows or changing slots.
Changsha's rectangular view preserves the traditional table topology. Every
wall pose is the source pose plus POV rotation only, including vacant draw
positions and both stack tiers. Four fixed six-column/three-row discard rivers
fit inside the wall ring. Outside it, each player's exposed melds and remaining
hand share a row. The local separate band contains both hand and melds, without
a duplicate table copy; concealed targets retain useful touch widths while
public melds use smaller adjacent clusters. Added Kong tiles retain their
source stacked relationship. Empty meld reserves do not enlarge the table.
Source slot addresses, face entitlement, rule geometry and draw order remain
unchanged. The original tile artwork, bevels, felt, rail and shadows are retained.
The traditional perspective profile is a steeper78..88-degree oblique view so
side-player faces remain readable without moving or stretching the wall.
Every schema group/kind is represented, including sticks, marker, Kita and
Minefield wall.open. Four/three/two-seat active players remain source-defined;
extra physical wall/payment slots may exist on otherwise inactive sides.
Separate hand uses explicit LocalHand order, the same actor's exposed melds,
camera layer/band, fitted rows and a drawn-tile gap. A viewSeat change never
creates actor/hand entitlement.
Known entitled faces are drawn only when showFace is true; concealed surfaces
use a common back and carry no face label/texture index.
Flat/perspective, zoom/lookDown, viewSeat, CSS/DPR/insets and orientation refit
are frame/viewport inputs. Changed picking transforms cancel gestures and
block picks until the corresponding camera plan is committed.

Native input: mouse/touch raycasts, single touch discard when authorized,
tap selection/manual pickup/dice, mouse double-click discard or eligible relay
double-tap flip, right-click/F flip, Shift/Ctrl or touch-long-press
multi-selection, source-authorized relay slot drag/drop and cancel. Source
canSelect/canDrag/canFlip/canDiscard/canPickup flags are checked at action time.
Changsha commands never relocate a tile locally. Submitted is not a server ack.
Multi-touch cancels active dragging; no zoom/seat/sticky action is invented.
Moved/canceled/long-pressed touches do not discard. Touch-generated mouse input
is suppressed, and a released gesture cannot emit twice. Portrait automatic
camera mode is flat; desktop/landscape remains perspective. Explicit camera
and classic/rectangular/hand choices persist through orientation changes.
Browser preferences and rule/result/claim controls remain browser-owned.

Unqualified frozen-v1 gaps
-------------------------
Held Render.place can cross source groups while Thing/Slot metadata retains
the original address. Rectangular mapping preserves that original group and
supplied pose; it cannot infer shiftSlot/rules. Cross-group held rectangular
visual translation is unqualified pending real evidence/future boundary choice.
Sticky checkbox semantics have no v1 Configure/Presentation field. Native
gestures use explicit press/release; Frontend keeps the control visibly disabled
with an explanation rather than silently inventing behavior.

without the actual licensed producer and subsequent integration evidence.
